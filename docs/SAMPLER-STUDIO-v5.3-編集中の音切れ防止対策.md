### ❌ 今回見つかった問題と修正内容

#### 1. **BGM 再生中にファイルをドロップして差し替え → 即停止クリック**（v5.3 で修正）
- **原因**: `doBgmLoadFile` 内で `_doBgmDetach(slot)` を呼ぶと、`audio.pause()` が即実行される。BGM 再生中ならクリックノイズ発生。
- **修正**: `_doBgmDetachAsync()` を新設。再生中なら 25ms フェードアウト → audio.pause → 元 gain 復元 → detach。`doBgmLoadFile` から `await _doBgmDetachAsync(slot)` を呼ぶように変更。

#### 2. **BGM CLEAR 時に fade と detach のレース**（v5.3 で修正）
- **原因**: `doBgmClear` が `doBgmStop()`（setTimeout でフェード）→ 即 `_doBgmDetach()` を呼んでいた。setTimeout が解決する前に detach が走るのでフェードが効かない。
- **修正**: `_doBgmDetachAsync()` 一本化。`await` で順序を保証。`doBgmClear` を async 化。

#### 3. **PRESET LOAD 中の active 再生クリーンアップなし**（v5.3 で修正）
- **原因**: パッド再生中に PRESET LOAD すると、active source は古い buffer を保持して鳴り続けるが、pad の state は新プリセットに置換される。再生終わりに UI 不整合の可能性。
- **修正**: `loadPresetByName` の冒頭で `stopAll()`（anti-click フェード付き）→ 80ms 待機 → state 置換。

#### 4. **NEW PRESET 時の active 再生クリーンアップなし**（v5.3 で修正）
- **原因**: 同上。
- **修正**: `newPreset` を async 化、`stopAll()` → 80ms 待機 → `initBanks()`。

#### 5. **`playPad` の `source.start()` が try-catch なし**（v5.3 で修正）
- **原因**: 既に start 済みの source や、無効な引数で例外が出ると、関数全体が中断し state が不整合になる可能性。
- **修正**: `source.start()` を try-catch でラップ、失敗時は source/gain を即 disconnect してから return（リーク防止）。`gain.setValueAtTime` 等の audio param 呼び出しも try-catch でラップ。

### 音が止まる事故が起きないように対策済み

- **AudioContext 自動復帰**：システムスリープ・タブ切替で自動 resume
- **PAUSE 中は復帰させない**：ユーザー意図を尊重
- **start() 失敗時のリーク防止**：例外が出ても source/gain は disconnect
- **gain ノードのクリーンアップ**：すべての onended で disconnect、長時間運用でも蓄積しない

## 残ってる小さな限界（将来検討事項）

### 1. POLY モードの無制限スタッキング
同じパッドを 10 回以上連打すると、active source が積み上がる。各 source の gain は通常通り適用。理論上はメモリ蓄積するが、再生終了で disconnect されるので長くて数秒で消える。実用上問題は起きにくいが、将来「pad ごとの同時最大数」を設定可能にすることを検討。

### 2. シャットダウン時の保存
ブラウザを閉じる時、localStorage / IndexedDB の最終保存が走らない可能性。重要な編集は手動で SAVE → PRESET にすることを推奨。

### 3. BGM 再接続のリトライ
USB オーディオ機器を抜き差しした時、Chrome が `statechange` を発火するが、Web Audio の AudioContext と HTMLAudioElement の関係で稀に音が出なくなることがある。その場合は **Cmd+Shift+R で強制リロード** で復旧する。
